# 정상 용어 나열 자막 보존

2026-10-11, 최신 main `38279b6`을 반영한 guhyeon에서 작업했다.
2026-10-12 사용자 요청으로 guhyeon에 커밋·푸시한다. 실기기 결과는 아직 보고되지 않았다.
다른 팀원의 doyu stash는 보존했다.

## 문제와 근거

`src/stt/transcriber.py`는 전사 결과의 쉼표·공백 항목 중 80% 이상이 hotwords에
해당하면 결과 전체를 지웠다. 실제로 “이산화탄소, 포도당”이라고 나열한 정상 발화도
삭제될 수 있는 코드 경로다. 참가자가 이 문장을 실제로 발화했다는 보고는 아니다.

## 변경

- 기존 거의 무음(no_speech_prob > 0.85)·매우 낮은 신뢰도(avg_logprob < -1.3) 필터는 유지한다.
- 용어 나열 형태만으로 삭제하지 않는다. 나열 형태이면서 no_speech_prob > 0.5 또는
  avg_logprob < -0.8일 때 해당 세그먼트만 제외한다. 같은 발화의 다른 정상 설명은 유지한다.
- 위 두 추가 기준은 config의 echo_no_speech_prob·echo_avg_logprob에서 조정한다.
  실험으로 최적화한 값이 아닌 초기 기준이며, 모델의 수치는 정확도 확률과 동일하지 않다.
- 발화별 사전 스냅샷으로 hotwords와 나열 검사 기준을 맞춘다. 전사 중 과목을 바꿔도
  이번 발화가 다음 과목 사전으로 검사되지 않는다.
- 모델·추론 횟수·의존성을 추가하지 않으며, 음성과 전사 원문을 별도 진단 파일에 저장하지 않는다.

## 실기기 확인

자동 테스트는 전체 63개가 통과했다(9.157초). 기존 55개에 정상 나열 보존·낮은 신뢰도
나열 제외·정상 설명 보존·기존 무음 방어·과목 변경·빈 결과·설정 조정의 회귀 테스트
8개를 추가했다. STT 출력과 신뢰도를 모의한 테스트로, GPU 인식률 측정은 아니다.

앱을 재실행하고 과학을 선택한 뒤 다음을 확인한다.

1. “이산화탄소, 포도당”과 “이산화탄소, 포도당, 광합성”을 자연스럽게 말한다.
2. “광합성에는 이산화탄소가 필요합니다”처럼 설명 문장도 말한다.
3. 조용한 상태와 일반적인 교실 잡음에서 말하지 않았는데 용어가 나오는지 확인한다.
4. 발화 전사가 진행되는 동안 과목을 바꾸고 다음 발화가 정상 처리되는지 확인한다.

실제 오인식 사례는 의도한 문장·표시된 자막·과목·주변 소음 조건을 함께 기록해
필터와 사전을 조정한다. 이 변경은 필터에 의한 누락 개선이며, 모델 자체의 자연발화
인식 정확도 향상이나 전체 CER 개선을 입증한 결과는 아니다. 신뢰도가 낮은 실제 나열은
여전히 제외될 수 있고, 신뢰도가 높은 환각은 통과할 수 있어 실기기 검증이 필요하다.

### 2026-10-17 비정상 연속 반복 방어
- 20:39:58 수업 기록에서 한 결과 안에 '오'가 111회 나타나는 사례를 확인했다. 20:40:57의 짧은 2.016초 입력은 전사에 4.70초가 걸렸으며 기존 신뢰도 필터를 통과했다. 원음이 없어 두 기록의 직접 대응과 음향 원인은 확정하지 않는다.
- doyu stash의 미적용 반복 방지 코드를 guhyeon으로 가져오고 한 글자 반복도 처리하도록 보완했다. stash 원본은 보존한다.
- `src/stt/repetition.py`: 음성 길이 대비 영숫자 밀도가 초당 35자를 초과할 때만 검사한다. 같은 1~20개 단어 구절이 4회 이상 반복되고 제거 대상이 32자 이상이면 첫 구절을 남긴다. 4자 미만의 짧은 구절은 최소 16회 반복돼야 한다.
- 정상적인 소수 반복·느린 실제 반복·다른 단어 목록·앞뒤 설명은 보존한다. 한 글자 반복 기록은 재처리 시 334자에서 4자로 줄었다. 원본 저장 파일은 변경하지 않았다.
- 자막과 수업 기록으로 전달하기 전에 적용하며 `repetition_removed` 수치만 진단에 추가한다. 원문을 진단 로그에 추가하지 않는다. 추가 모델 추론은 없다.
- 밀도가 낮은 반복은 남을 수 있고 매우 빠른 실제 반복은 줄어들 수 있다. 이 방어는 모델의 반복 생성 자체를 해결하지 않으며 실제 마이크 재시험이 필요하다.
