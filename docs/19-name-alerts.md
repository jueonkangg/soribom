# 이름 알림의 대상·부분 일치 수정

2026-10-12, main `98d9856`을 기준으로 guhyeon에서 구현했다.
사용자 요청으로 이름 알림·hotwords 개선과 해결 확인 기록을 함께 커밋·푸시하고 main에 통합한다.

## 코드에서 확인한 문제

`src/events/sound_events.py`는 어떤 이름이 감지됐든 등록된 이름 전체 중 가장 짧은 이름을
알림에 표시했다. 여러 학생이 등록됐을 때 다른 학생을 표시할 수 있었다.
단순 부분 일치는 짧은 이름이 다른 단어 안에 있을 때도 알림을 만들었다.
둘 다 코드 검토에서 확인한 경로이며 참가자의 실제 오탐 보고와 구분한다.

## 변경

- 실제 전사에서 감지한 등록 이름을 그대로 표시한다. 성을 임의로 생략하거나 별명과 동일인으로 묶지 않는다.
- 단어 시작의 이름과 뒤의 공백·문장부호를 인식한다. “도유야”, “도유는”, “도유에게”처럼
  일반적인 한국어 호격·조사가 붙은 경우도 허용한다.
- “민”을 등록해도 “국민”, “민주주의”에 반응하지 않는다. “도유”만 등록했다면
  “함도유” 전체를 부분 일치로 감지하지 않으므로 필요한 전체 이름과 호칭을 함께 등록한다.
- 한 발화의 알림은 기존처럼 한 번이다. 텍스트에서 먼저 나온 이름을 선택하고,
  같은 위치에서 여러 등록 이름이 맞으면 긴 이름을 선택한다.
- 빈 이름·중복 이름은 제거하고 등록 이름은 정규식 명령이 아닌 글자 그대로 검사한다.

새 모델·추론·음성 저장은 추가하지 않는다. 전체 자동 테스트 72개가 통과했다(9.108초).
기존 63개와 이름 알림 회귀 9개를 포함하며, 실제 음성 인식 정확도 측정은 아니다.

## 실제 앱 확인

앱을 재실행한 뒤 기본 등록 이름으로 “함도유 학생”, “도유야 대답해 줘”를 말해
표시된 자막과 알림의 이름이 일치하는지 확인한다. 여러 학생을 시험하려면 설정에
각 이름을 등록한 뒤 재실행하고, 감지한 학생의 이름이 표시되는지 확인한다.

STT가 이름을 잘못 전사하면 감지가 누락되거나 잘못될 수 있다. 이름 언급과 직접 호명을
의미로 구분하는 기능은 아니므로 “도유는 결석입니다” 같은 언급도 알림이 된다.
등록한 호칭이 다른 일반 단어와 같거나 전사 띄어쓰기가 잘못되면 오탐·누락이 남는다.
조사가 여러 개 붙은 표현 등은 지원 목록에 따라 누락될 수 있어 실제 사례로 보완한다.

## 호명 표현 hotwords 보강 (2026-10-12)

사용자가 “함도유”, “도유야”, “도유 학생”, “함도유 학생”이 잘 인식되지 않는다고 보고했다.
제공된 화면에도 이름이 다른 글자로 전사된 사례가 보였다. 알림 검사 전 단계인 STT의
실기기 오류 보고이며, 이름 알림 수정이 실제 음성까지 정상 동작했다는 확인은 아니다.

사용자 선택에 따라 등록 이름별로 원래 이름·띄어 쓴 학생 호칭·붙여 쓴 학생 호칭·호격을

영어 사전은 영어 수업의 한국어 문법 용어이며, 영어 음성 인식 모드 구현을 뜻하지 않는다.

앱 재실행 후 같은 거리·음량에서 위 네 가지 호칭을 여러 번 말해 자막과 알림을 확인한다.
무음에서 이름이나 추가 용어가 저절로 나오지 않는지도 확인한다. hotwords는 인식 힌트이므로

## 재시험 실패와 실제 토큰 제한 수정

사용자의 00:38:38 화면에서 “도요”, “도요야” 등 오인식이 지속됐다. 설치된
faster-whisper의 `WhisperModel.get_prompt`를 확인하니 hotwords는 최대 223토큰만
앞에서 사용한다. small의 실제 로컬 토크나이저로 측정한 기존 과학 문자열은 490토큰,
경제는 1,112토큰이었고, 223토큰으로 잘린 결과에는 등록 이름이 없었다.
직전 main도 각각 406·1,028토큰이고 등록 이름이 잘려, 최근 변경만의 회귀라고 단정하지 않는다.
앞선 모의 테스트는 문자열에 이름이 존재하는지만 검사해 이 제한을 놓쳤다.

수정 후 등록 이름·호칭을 먼저 배치하고 과목·공통 용어를 번갈아 넣는다. 모델의 실제
토크나이저와 max_length로 길이를 재고 완전한 용어 단위로 선택한다. 제외된 사전 항목은
파일에 그대로 보존한다. 첫 실행·과목 변경 때만 선택하며 모델을 추가하거나 재로딩하지 않는다.
필터도 실제 선택된 힌트만 기준으로 삼는다. 터미널에는 선택한 개수·최대 토큰 수만 표시한다.

실측 선택 결과는 과학 56/136개·222토큰, 경제 56/250개·223토큰이며,
5개 과목 모두 기본 등록 이름의 8개 이름·호칭 표현이 실제 프롬프트에 포함됨을 확인했다.
사전 선택 시간은 과목에 따라 약 41~85ms였다. 토큰 한도로 모든 사전 용어가 동시에
적용되는 것은 아니며 필요한 수업 용어는 사전 앞부분에서 우선 관리한다.

전체 79개 테스트가 통과했다(9.953초). 이번에는 실제 로컬 토크나이저와 라이브러리
프롬프트 생성 경로로 잘림이 없는지를 검증했다(GPU 추론 없음). 수정 직후 실기기 재시험을 요청했다.

## 실기기 해결 확인·다음 작업자의 주의점

2026-10-12 사용자가 00:44:39 스크린샷과 함께 “해결됐다”고 확인했다. 화면에는
“함도유학생”, “도유야”, “도유야, 오늘 광합성 잘 이해했어?”, “함도유야”가 정확히 표시된다.
호칭 단독과 과학 수업 문장에서 이름 인식이 회복된 실사용 확인이다. 이 화면에는 이름 알림이
보이지 않으므로 알림 표시까지 검증했다고 기록하지 않는다. 무음 오탐·다른 이름·다른 과목·
장시간 인식률은 별도 확인 대상이며 전체 CER 개선을 측정한 결과가 아니다.

발견의 근거와 재발 방지 기준:

1. **제한은 단어 수가 아닌 실제 토큰 수다.** 현재 설치된 faster-whisper 1.2.1의
   `WhisperModel.get_prompt`는 `max_length // 2 - 1`을 넘는 hotwords를 앞에서 자른다.
   현재 모델 max_length=448에서 223토큰이다. 버전·모델을 바꾸면 구현과 값을 다시 확인한다.
2. **사전에 저장됐다는 것과 모델이 사용하는 것은 다르다.** 긴 문자열 뒤의 이름은 선택되지
   않았으며, 용어만 추가한 첫 수정도 효과가 없었다. 이름·호칭을 우선 배치하고 실제
   토크나이저로 완전한 항목을 선택하는 현재 방식을 유지한다.
3. **테스트는 최종 프롬프트까지 확인한다.** 문자열 포함 검사만으로는 잘림을 발견하지 못했다.
   `test_actual_whisper_tokenizer_keeps_names_within_library_budget`는 실제 로컬 토크나이저와
   라이브러리 프롬프트를 검사한다. 로컬 모델 파일이 없어 이 테스트가 skip되면 검증 완료로
   간주하지 말고 모델이 있는 환경에서 실행한다.
4. **사전 확장 후에는 이름과 수업 문장을 함께 재시험한다.** 제한 안에 모든 사전 항목이
   들어가지는 않는다. 과목 사전 앞부분에 필요한 용어를 배치하고, 터미널의 선택 개수를
   확인한다. 등록 이름이 많아지면 기본 8개 호칭의 현재 검증 결과를 그대로 적용하지 않는다.
