# 입력 연속성과 전사 대기 개선 — 2026-10-13

## 문제와 수정

[낭독 시험](22-reading-experiment-results.md)에서 콜백 전송 시각 간격 이상이 59회,
원시 음성 큐 포화가 17회 발생했다. 기존의 짧은 간격 이상 초기화는 진행 중 발화와 전사
결과까지 버릴 수 있었다. 주기 현상의 하드웨어/드라이버 원인 자체를 확정한 것은 아니다.

1. 캡처 프레임에 콜백 순번·콜백 monotonic 시각·ADC/PortAudio 현재 시각·입력 overflow 누계·
   비차단 파이프 전송 실패 누계를 추가했다. 콜백 안의 경고 문자열 출력은 제거했다.
   PIPE_BUF 이하 원자적 쓰기·비차단 전송은 유지했고 패키지는 추가하지 않았다.
2. 순번 누락·입력 overflow 증가·ADC 시각 불연속으로 실제 유실을 판단한다. ADC는 유효할
   때만 사용하고 10ms 오차를 허용한다. 콜백 시각만 늦으면 callback_jitter를 기록하며
   큐/발화를 초기화하지 않는다. ADC가 없으면 순번/overflow로 판단한다.
3. 실제 유실은 기존 큐에 빈 경계 블록을 넣는다. VAD는 최소 발화 길이를 충족한 유실 전
   발화를 먼저 내보낸 뒤 문맥을 비운다. 유실 뒤의 음성을 앞과 붙이지 않는다.
   연결 세대를 바꾸지 않아 이미 완성한 이전 발화의 전사 결과도 게시된다.
4. USB 재연결·입력 장시간 중단·원시 큐 포화는 기존 세대 차단을 유지한다.
   큐가 꽉 찬 상태에서 경계를 넣는 경우도 포화 처리 대상이다. 모든 유실을 없애지는 못한다.
5. VAD 1개/STT 1개의 고정 워커로 분리해 추론 중에도 원시 입력을 소비한다.
   모델을 복제하거나 발화마다 워커를 만들지 않는다. 대기 큐는 최대 4발화이며 포화 시 가장
   오래된 대기 발화를 버린다. 발화 끝부터 6초 이상 지난 발화는 추론 전에 제외한다.
   발화 종료 시각이 없으면 큐 삽입 시각을 쓴다. 추론 중인 발화는 중간 취소하지 않는다.
6. 정상 종료 때 대기 큐를 닫고 비워 워커의 대기를 해제한다. 종료 정리는 유실 카운터에
   포함하지 않는다. 전사 대기 삭제와 원시 음성 블록 삭제는 별개로 집계한다.

ADC 기준 블록 끝 시각은 콜백 monotonic에 ADC와 PortAudio 현재 시각의 차이·블록 길이를
반영한다. 별도 시계·콜백 지연의 측정 오차는 남으며 실제 화면 렌더 시간은 아니다.

## 설정과 진단 해석

`audio.gap_tolerance_ms=10`, `stt.queue_max_utterances=4`, `stt.queue_max_age_seconds=6`.
추론보다 빠른 발화가 지속되면 유실된다. 대기 큐를 무제한 늘리지 않는다.

- audio_gap의 missing_blocks/capture_overflows/pipe_dropped_blocks는 해당 경계의 증가량이다.
  duration은 ADC 간격에서 블록 길이를 뺀 양의 공백이다. ADC가 없으면 0일 수 있다.
  duration=0이라고 유실이 없다는 뜻은 아니다.
- 자원 표본의 capture_overflows/pipe_dropped_blocks는 전체 세션 누계다.
  마지막 전송 실패 뒤 성공 프레임이 없으면 해당 실패를 부모가 받지 못할 수 있다.
- callback_jitter/callback_jitters는 순번·ADC·overflow상 유실 근거 없이 콜백 간격이
  블록 길이의 3배보다 벌어진 경우다. 장치 무결성을 보장하는 지표는 아니다.
- utterance_queue_depth/utterance_dropped는 새 전사 큐 깊이/삭제 발화 수다.
- 오류 operation은 transcribe/vad/publish, 고정 error_category는 memory/cuda/input/unknown이다.
  예외 메시지는 분류에만 사용하고 진단에 저장하지 않는다. 이전 RuntimeError는 소급 분류 불가다.
- analyze_diagnostics.py에 새 카운터와 오류 위치/분류 출력도 추가했다.

**수정 전 audio_gap은 콜백 시각 기준이었다.** 이전 59회와 새 횟수는 정의가 달라
횟수 감소만으로 실제 음성 유실 감소를 주장하지 않는다. 텍스트 누락과 함께 비교한다.

## 검증과 다음 시험

전체 **96개 테스트 통과(9.931초)**. 신규 회귀 8개는 jitter에서 큐/세대 보존,
실제 순번/ADC/overflow 유실 경계, 파이프 유실 누계 전송, 유실 전 VAD 발화 보존과
재연결 폐기, 유한 큐 포화/오래된 발화/종료 대기 해제, 안전한 오류 분류를 검증한다.
기존 main 통합 시험도 STT가 기다리는 중 VAD 진행을 검증한다.
기존 실제 자식 프로세스 반복 재연결·방향·기록·UI 테스트도 통과했다.

수정 후 실제 USB/Jetson GPU 낭독은 아직 하지 않았다. 앱을 완전히 재실행하고 국어·같은
작품 사전·같은 스마트폰 위치/볼륨/속도로 1부 앞 5~10분을 재생한다. 이전 첫 누락 후보는
앱 시각 21:52:22 부근이었으나 재생 시작 시각은 미확인이라 MP3 고정 초 위치로 단정하지 않는다.
새 진단의 jitter/ADC gap/overflow/파이프 유실과 텍스트 누락·지연을 대조한다.
개선 확인 후 전체 51분 낭독 및 TTS/USB 재연결 시험으로 확장한다.

**중요한 실기기 근거:** 약 53초마다 발생하던 콜백 시각 흔들림은 여전히 관찰됐다.
그러나 순번/overflow/유효한 ADC 검사에서 유실 근거가 감지되지 않아 jitter로만 기록했고,
모든 게시 자막은 세대 0을 유지했다. 세대 1은 정상 종료 초기화 때만 나타났다.
이는 이전에 콜백 간격만으로 발화를 초기화하던 판단을 개선한 근거다.
ADC 가용 여부 자체의 별도 카운터는 없으므로 모든 ADC가 유효했다고 단정하지 않는다.

이전의 첫 누락 후보 “작은 여신의 … 다리를 뻗고”가 이번에는
“작은 여신의 젖과슨 같은 부드러운 풀포기의 다리를 벗고”로 기록됐다.
문장 누락은 완화됐지만 단어 오인식은 남아 있다.
