# 말하기 출력 정체와 입력창 잠김 수정 — 2026-10-13

18시 후속: 이 수정은 브랜치 이동 때 stash에 보관되어 doyu에는 빠져 있었다.
사용자의 먹통 재발 보고 후 stash를 보존한 채 doyu에 복원했다. 과목별 언어 인식과
합친 자동 테스트 115개가 통과했으며, 복원한 수정은 아직 미커밋/실제 재시험 전이다.

## 확인한 현상과 근거

사용자가 제공한 최신 화면(02:34:01)에서 자막은 갱신됐지만 말하기는 계속
“말하는 중…”이었고 입력창과 Enter 요청이 비활성 상태였다.
진단 세션 `10a0e8297aab497d801c5cdcd5f47656`의 같은 시점을 확인했다.

- 요청 02:33:34.233, 합성 완료 02:33:36.132: 합성 약 1.899초, 음성 길이 약 1.546초.
- 출력 제출 02:33:36.148 이후 정상 완료가 없었다.
- 앱 종료 시각인 02:34:04.489에야 `SpeechOutputError`로 끝났다. 전체 요청은 30.256초였다.
- 해당 기간 자막은 계속 처리됐고, 큐 삭제·자막 오류는 기록되지 않았다.

직전 변경에서 도입한 블로킹 출력 `write()/stop()` 경로가 반환되지 않아 UI가 완료 신호를
받지 못한 문제다. 기록만으로 write와 stop 중 어느 호출이 멈췄는지는 구분할 수 없다.
GPU 합성 지연이나 자막 오류로 입력창이 잠겼다고 볼 근거는 없다.

## 구현한 동작

아래 1·2번은 최초 콜백 출력 수정이다. 이후 Bose 재연결 때 시작 단계 오류를 확인해
기본 경로를 별도 재생 프로세스로 변경했다. 최신 경로와 시스템 설정은 아래 후속 기록을 따른다.

1. 합성된 음성을 출력 콜백에 짧게 복사하고 마지막 블록에서 `CallbackStop`을 사용한다.
   출력 버퍼의 재생이 끝나면 `finished_callback`이 완료를 알린다.
   블로킹 write와 버퍼 배출을 기다리는 stop을 재생 경로에서 제거했다.
2. 완료 대기는 음성 길이 + 3초로 제한한다. 시간 초과/출력 중단 때 스트림을 정리하고
   실패를 안내하며 다음 요청에서 새로 연다. 무제한 대기 스레드를 추가하지 않는다.
   종료 때 완료 대기도 깨운다. PortAudio 자체의 시작/정리 호출에는 별도 프로세스 타임아웃을
   적용하지 않으므로 모든 드라이버 고착을 이 한도로 제한한다고 보장하지 않는다.
3. 재생 중 입력창을 계속 편집할 수 있다. 성공 시 보낸 문장과 입력창이 같을 때만 지운다.
   다음 문장을 입력했다면 그대로 남긴다. 중복 재생 방지를 위해 재생 중 Enter/버튼의 새 요청은
   받지 않고, 완료 또는 실패 후 다시 사용할 수 있다.
4. 사용자의 후속 선택에 따라 현재 전사가 끝난 뒤 말하기를 우선하고, **합성부터 재생 완료까지**
   다음 STT를 기다리게 한다. 성공·실패·시간 초과 어느 경우든 게이트를 해제해 STT를 재개한다.
5. 마이크와 VAD는 계속 수음한다. 대기 중인 발화와 말하기 중 수음한 발화를 FIFO로 보관한다.
   이 발화에는 평소 6초 만료를 적용하지 않는다. 보관된 발화가 처리되는 동안 들어온 후속 발화도
   같은 순서로 처리한다. 큐는 최대 32발화로 제한하며 넘으면 가장 오래된 발화를 삭제하고
   기존 `utterance_dropped`에 집계한다. 평상시에는 기존 4발화/6초 제한으로 돌아간다.

## 의도한 한계

보관 후 전사를 선택했으므로 재생 중 자막은 기다리고, 재생이 끝난 뒤 지연된 자막이 나온다.
마이크가 스피커 음성을 듣는 경우 소리봄 자신의 말소리도 전사될 수 있다. 에코 제거는 구현하지 않았다.
보관은 메모리 내에서만 하므로 앱 종료 시 대기 중 음성은 사라진다. 32발화 초과도 무손실을 보장하지 않는다.
30초 발화/16kHz float32 기준 큐 음성은 최대 약 59MiB이며 메타데이터·처리 중 발화는 별도다.

출처와 선택: 출력 정체는 사용자 화면·진단 기록에서 확인했고,
재생 중 입력을 보관하는 방식은 사용자가 명시적으로 선택했다.
콜백 출력·완료 시간 제한·32발화 한도는 이 문제를 해결하기 위한 구현 판단이다.

  합성·출력 실패 후 복구, 재생 중 다음 문장 보존, STT가 재생 후 재개되는 순서,
  보관 발화의 만료 제외·FIFO·한도 초과 집계를 검증했다.
- 현재 Bose는 연결됐으며 시스템 기본 출력으로 지정했다.
- 실제 Jetson GPU STT 4회와 Bose TTS 2회를 같은 게이트에서 실행했다.
  두 재생 모두 성공, 요청→재생 완료 **3.426/4.096초**, 합성 약 **1.51/1.47초**,
  음성 약 **1.9초**. 전사 작업도 모두 종료했고 오류는 없었다. 스트림 재사용도 확인했다.
- 이 시험의 STT 입력은 고정 무음이며 실제 마이크 동시 입력·자막 표시·청감 잡음은 확인하지 않았다.
  첫 음절이 들리는 시각도 별도 측정하지 않았다. 앱에서 실제 동시 입력 재시험이 필요하다.
- 사용자 지시에 따라 일본어를 사용하지 않는 규칙을 CLAUDE.md에 추가했다.
  프로젝트 텍스트 검색에서 일본어 가나 문자는 발견되지 않았다.

앱을 다시 실행하고 말하기를 요청하는 동안 마이크에 계속 말한다.
다음 문장 입력이 가능하고 재생 후 순서대로 자막이 갱신되는지 확인한다.
이어 다음 문장을 Enter로 보내고, 새 진단의 출력 오류·추론 대기·발화 삭제를 확인한다.

## Bose 출력 오류·잡음 후속 수정

세션 1e6b039ff233494f85fae199a5f879e0의 말하기는 합성 1.874초/음성 1.360초였지만
재생 시작 기록 없이 약 12.259초에 SpeechOutputError로 끝났다. 합성 이후의 출력 시작
경로에서 실패한 것으로 좁혔다. PortAudio 내부 또는 Bluetooth 드라이버의 정확한 원인은 미확정이다.

현재 기본 출력은 `tts.output_backend: pulse`이다. 설치돼 있던 paplay를 매 요청마다 새로 열어
현재 Bose A2DP 싱크에 출력한다. 예전 스트림/장치 인덱스를 재사용하지 않고, 원시 float32 음성을
표준 입력으로 전달해 디스크에 저장하지 않는다. 재생 시간 제한은 음성 길이+3초이며,
시간 초과·출력 실패·앱 종료 때 프로세스를 회수한다. PortAudio 시작/정리 호출은 이 경로에 없다.
`sounddevice` 경로는 명시적으로 선택할 때만 사용한다.

Bose 싱크가 없으면 합성 전에 해당 스피커의 재연결만 시도한다. 연결 명령은 외부 프로세스
제한 6초, 출력 싱크 준비 대기는 최대 약 2초와 조회 제한으로 묶었다. 연결 확인 동안 자막은
추론 게이트를 점유하지 않아 계속 진행한다. 실패하면 입력을 유지하고 다른 출력으로 보내지 않는다.
스피커가 연결 대기 상태가 아니면 자동 복구를 보장하지 않는다. 부분 재생 후 자동 재전송은 없다.

시스템에서 오디오 서비스 재시작과 A2DP 확인만으로는 사용자가 잡음이 남는다고 보고했다.
NYA-T 5GHz 연결은 인증 정보가 없어 실패했고 NYA-S로 복구했다. 그 뒤 NYA-S의
Wi-Fi 절전을 `2 (disable)`로 설정하고 연결을 갱신해 `Power save: off`를 확인했다.
사용자가 재생 후 '깨끗하게 들림'이라고 확인했다. Wi-Fi 절전/무선 공존 문제가 유력한 후보이지만,
Wi-Fi 재연결 효과와 절전 해제 효과를 분리한 시험은 하지 않아 드라이버 내부 원인은 미확정이다.

Bose 출력에만 대기 중 중단을 막는 WirePlumber 0.4 규칙을 적용했다.
원본은 `scripts/90-soribom-bose.lua`, 적용 위치는
`~/.config/wireplumber/bluetooth.lua.d/90-soribom-bose.lua`다.
출력 노드의 suspend timeout 0과 재생 후 IDLE 상태를 확인했다. 이 설정은 연결이 끊기는 모든
무선 문제의 해결을 보장하지 않는다. 되돌릴 때는 이 파일을 제거하고 WirePlumber를 재시작한다.
Wi-Fi 설정 원복은 `nmcli connection modify NYA-S 802-11-wireless.powersave 0` 후 연결 갱신이다.

검증: 전체 126개 테스트 통과(10.544초). 실제 GPU 말하기 두 번, 7초 대기 후 두 번 재생 성공.
강제 연결 해제 뒤 최초 재연결은 실패했으며 사용자가 스피커를 껐다 켜고 연결 대기 상태로
만든 뒤 새 출력 경로에서 약 5.038초에 준비, 약 8.174초에 재생 완료했다.
STT/TTS 두 모델을 함께 읽은 별도 실제 GPU 전사 시험 8회도 완료했다. 이전 간헐적 GPU
메모리 실패의 완전한 해결이나 장시간 Bluetooth 안정성을 뜻하지는 않는다.

최종 통합 세션 da4a8b8838e642578ab852214cd290a5에서는 실제 두 모델·마이크·방향과 Qt
말하기 요청 경로를 함께 사용했다. 두 번의 요청이 각각 4.356/5.039초에 성공하고,
두 번째 재생 뒤 실제 마이크 전사가 0.681초에 완료됐다. 이는 요청→재생 완료 시간이며
첫 소리 지연은 아니다. 입력 유실·전사 삭제·오류 기록은 없었고 기록 저장과 정상 종료도 확인했다.
최종 전체 126개 테스트 통과(10.616초). 종료 후 Bose Connected=yes와 Wi-Fi 절전 off를 확인했다.
