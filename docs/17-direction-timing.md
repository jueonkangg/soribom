# 발화 시점과 자막 방향 연결

2026-10-11, main `521776d`를 반영한 doyu에서 구현. 사용자 요청에 따라 doyu 커밋·푸시 후 main에 통합하는 변경이다.
기존 기록·말하기 개선은 `521776d`로 origin/main과 origin/jueon에 공유했다. 팀원 stash는 보존했다.

## 동작

기존에는 발화가 끝난 뒤 방향을 읽어 다음 화자의 각도가 앞 자막에 붙을 수 있었다.
이제 수음 블록의 시각을 VAD까지 전달하고, 방향 워커 하나가 기본 0.1초 간격으로 모은 표본 중
실제 발화 구간에 속한 값만 연결한다. USB 읽기 시작·완료가 모두 발화 안에 있어야 채택한다.
전사 오디오의 앞 패딩·끝 침묵은 유지하지만 방향 집계에서는 제외한다.

원본 각도를 발화별로 집계해 이전 화자의 평활화 관성을 남기지 않는다. 기본 ±30도 안에
표본의 70% 이상이 모이고 최소 2개가 있어야 주된 원형 방향을 표시한다. 부족하거나 크게
갈리면 화살표를 지우고 **화자 방향 (미확정)**으로 표시한다. 화자 신원 식별·화자별 전사는 아니다.

## 자원·장애

- 표본은 기본 60초·최대 602개, 설정을 늘려도 최대 2,000개로 제한한다.
- 집계 중 음성 큐 잠금을 잡지 않으며, 마이크·방향 워커와 녹음 프로세스 수를 늘리지 않는다.
- 검증된 DOAANGLE만 읽는다. USB 300ms 제한과 기존 오류·재연결 처리를 유지한다.
- 재연결 세대가 다르거나 만료된 표본, 늦은 USB 응답을 쓰지 않는다. 장애·종료 시 표본을 정리한다.
- 침묵 중도 표본을 모으지만 VAD가 음성으로 판정한 시간만 화면에 사용한다.

설정은 `src/config.yaml`의 `doa.sample_seconds`, `history_seconds`, `min_samples`,
`cluster_window_degrees`, `min_consensus`다. `vad.timestamp_tolerance_ms`(기본 10ms)는
콜백의 작은 시간 흔들림만 허용하며 32ms 무음 창은 합치지 않는다.

## 검증

전체 **55개 테스트 통과**, 9.185초. 이전 44개에 방향 시점 10개·통합 경로 1개를 추가했다.
STT 중 다음 화자 표본 도착, 화면·노트 전달, 침묵·늦은 읽기 제외, 대립 방향 미확정,
359/1도 경계, 표본 한도·만료, 재연결 세대, 480샘플 수음과 512샘플 VAD 창의 시각,
긴 발화 분할·USB 주기 제한을 모의 테스트로 검증했다. 재실행에서도 55개 모두 통과했다(9.336초).

사용자가 실기기 테스트 스크린샷 4장(22:06:42~22:07:55)을 제공하고 예상대로 작동한다고
확인했다. 화면에서 연결 끊김 안내·기존 자막 유지·화살표 제거·연결 복구·새 자막의 방향
표시 복귀를 확인했다. 실제 위치별 각도와 교대 발화별 결과·장시간 시험 수치는 제공되지 않았다.

## 실기기 확인 순서

1. 앱을 재실행하고 마이크·방향 연결 완료를 기다린다.
2. 앞·왼쪽·오른쪽에서 각각 1~2초 이상 말해 문장과 방향이 맞는지 확인한다.
3. 두 사람이 서로 다른 방향에서 번갈아 말한다. 첫 문장의 전사 중 다음 사람이 말해도
   앞 자막에 다음 방향이 붙지 않는지 확인한다.
4. 빠른 교대나 매우 짧은 발화로 표본이 부족해지면 미확정이 나올 수 있다. 자막은 계속 표시돼야 한다.
5. ReSpeaker 분리·재연결 시 오래된 화살표가 지워지고 새 발화부터 다시 표시되는지 확인한다.
6. 밝은/어두운 테마의 미확정 표시와 다음 정상 발화에서 화살표 복귀를 확인한다.

하드웨어 DOA와 VAD의 정확도에 의존하며, 콜백 시각에 하드웨어 내부 지연까지 정밀 보정한
결과는 아니다. 기존 7월 DOA 오차를 새 방식의 측정값으로 사용하지 않는다. 실제 교대 발화의
각도·누락·장시간 사용 결과를 별도로 확인한다.
