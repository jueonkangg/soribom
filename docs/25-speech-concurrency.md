# 말하기 지연·동시 추론 오류와 스피커 재연결 — 2026-10-13

후속 수정: 출력 정체·입력창 잠김을 확인해 콜백 출력으로 변경했고, 사용자 선택에 따라
STT를 재생 완료까지 기다리게 했다. Bose 연결도 복구됐다. 최신 동작은
[말하기 출력 정체 수정](26-playback-lockup.md)을 참고한다. 아래는 당시 조사 기록이다.

## 사용자 보고와 최근 기록

사용자는 Bose 스피커의 지속적인 잡음, Enter 후 말하기까지의 지연 증가,
말하기 중 마이크 입력이 있을 때 화면의 모델 오류를 보고했다.
최근 수업 진단 세션 `33919785cb6747ae84b90bd0b53810b5`는 약 111초 동안
자막 16건, 말하기 2건을 기록했다. 원시 큐/전사 큐 유실과 저장 실패는 없었다.

- 첫 말하기: 합성 3.544초, 출력 제출까지 4.346초. 두 시각의 차이는 약 0.802초다.
- 두 번째: 합성 2.349초, 출력 제출까지 2.407초.
- 두 번째 음성 **재생 중** 자막 전사에서 `RuntimeError`, `memory` 분류가 1회 발생했다.
  이후 자막은 다시 처리됐다. 말하기 자체는 두 번 모두 성공했다.
- RSS는 말하기 전 약 1,723MiB에서 이후 약 2,026MiB로 증가했고,
  표본의 시스템 가용 메모리 최솟값은 약 2,749MiB였다.

이 기록만으로 전체 시스템 메모리 고갈이나 TTS 모델 실패를 단정하지 않는다.
예외 원문을 진단에 보관하지 않으므로 원인은 미확정이며, 발생 시점은 합성 후 재생 중이다.

## 기기에서의 추가 측정

실제 Jetson의 small CUDA STT와 Supertonic CUDA TTS를 함께 로딩했다.
음질 설정 32스텝을 유지하고 고정된 한국어 시험 문장으로 측정했다.
이 시험에서는 합성 결과를 스피커로 재생하지 않았다.

| 조건 | 관찰 |
|---|---|
| 짧은 문장, 순차 추론 | 첫 합성 2.08초, 이후 1.30~1.52초 |
| STT 8회와 긴 문장 합성을 동시에 실행 | 첫 합성 5.75초, STT 종료 후 합성 1.80~1.93초 |
| 웜업 후 공유 추론 게이트 적용, STT 8회/TTS 2회 | TTS 요청→합성 완료 2.636/2.493초, 그중 대기 0.586/0.591초; 합성 자체 약 2.03/1.88초 |

동시 시험과 수정 후 시험에서 메모리 오류는 재현되지 않았다.
작은 횟수의 비교이므로 장시간 안정성이나 실제 들리는 시각을 보장하지 않는다.
다만 같은 기기에서 GPU 추론 경합이 말하기 지연에 기여할 수 있다는 근거는 확인했다.

## 구현

1. `src/inference.py`의 게이트로 STT/TTS 추론을 한 번에 하나씩 실행한다.
   기다리는 말하기 요청을 다음 자막보다 우선한다. 이미 진행 중인 전사는 중단하지 않는다.
   마이크/VAD는 계속 실행하고, TTS **재생 중에는** 자막 추론을 허용한다.
2. 모델 준비 중 STT 무음과 짧은 TTS 합성을 한 번 실행한다. 웜업 음성은 재생하거나
   수업 기록에 넣지 않는다. 첫 요청 준비 비용을 시작 단계로 옮기는 방식이다.
3. 출력 스트림을 준비·재사용해 매 요청마다 장치를 여는 비용을 줄인다.
   출력 실패 시 스트림을 닫고 다음 요청에서 새로 연다. 종료 시에도 닫는다.
   출력 버퍼는 `high`를 유지하고 32스텝을 줄이지 않았다.
4. 음성 합성 오류와 출력 오류를 구분해 UI에서 다른 안내를 표시한다.
   자막 메모리 오류는 자막 처리 오류로 명시한다. 실패한 입력은 재시도를 위해 남긴다.
5. 진단에 `models_warmup`, `inference_wait`, `inference_wait_s`를 추가한다.
   합성/전사 시간과 공유 추론 대기 시간을 나눠 분석하며 개인정보·예외 원문은 추가하지 않는다.

말하기를 우선하는 동안 자막 대기는 늘어날 수 있다. 기존 전사 큐 한도(4발화/6초)는
유지하므로 긴 합성과 지속 입력에서는 발화 삭제 카운터도 확인해야 한다.
GPU 직렬화가 모델의 상주 메모리나 각 런타임의 캐시를 해제하지는 않는다.
따라서 최근 재생 중 오류의 완전한 해결은 실제 동시 사용 재시험으로 확인해야 한다.

`tts_playback` 시각은 출력 스트림 시작 후 쓰기 직전의 제출 시각이다.
실제 첫 음절이 들리는 시각에는 출력 버퍼와 Bluetooth 지연이 추가된다.
마이크와 스피커를 함께 사용한 실제 Enter→첫 소리 시간은 아직 측정하지 않았다.

## Bluetooth 상태와 다음 검증

이전 해결 방식은 `docs/16-recording-speech-stability.md`의 페어링 보존·연결 해제/재연결이다.
사용자 요청에 따라 이번에도 Bose 연결을 해제하고 재연결을 시도했다.
현재 시도에서는 `br-connection-page-timeout`이 반복되어 스피커가 연결되지 않았다.
페어링/신뢰는 보존되어 있고, 컴퓨터 Bluetooth는 켜져 있으며 차단되지 않았다.
다른 Bluetooth 기기가 연결되지 않은 상태에서 컴퓨터 어댑터를 껐다 켠 뒤에도
같은 시간 초과가 발생했다. 어댑터 전원은 다시 켜 둔 상태다.
따라서 이번 잡음이 해결됐다고 판단하지 않는다. 스피커의 연결 대기 상태와
다른 기기 연결을 확인한 뒤 재연결하고, Bose를 기본 출력으로 지정해야 한다.

재연결 후 앱을 실행해 짧은/긴 문장을 입력하고, 그동안 마이크로 계속 말한다.
실제 잡음, Enter→첫 소리, 자막 오류, 전사 큐 삭제를 확인한다. 이후 최소 15~20분
동시 사용으로 확장한다. 오류가 다시 나타나면 새 진단의 단계와 대기/합성 시간을 비교한다.

기존 및 수정된 전체 자동 테스트 100개가 통과했고, 이후 추가한 3개 회귀 테스트도
UI 5개/스피커 8개 대상 검사에서 통과했다.
자동 테스트는 추론 우선순위·예외 후 게이트 해제·출력 재사용/실패 복구·중복 방지·입력 보존을
검증한다. Bluetooth 음질과 장시간 GPU 안정성은 자동 테스트의 보장 범위 밖이다.
