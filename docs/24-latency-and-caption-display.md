## 지연 감소 제안 (인식 설정은 아직 수정하지 않음)

1. 가장 간단한 조정은 발화 종료 무음 400→300ms다. 현재 32ms 창 때문에 실제 기준은
   416→320ms로 약 96ms 짧아진다. 최종 전체 지연 감소량은 추론 변동 때문에 보장하지 않는다.
   문장 중간 숨/짧은 멈춤에서 너무 잘리지 않는지 확인한다.
2. 말하는 동안 자막이 오래 안 뜨는 경우 최대 발화 길이 30→6~8초를 검토한다.
   발화 끝 지연과 별개의 체감 문제다. 문장/이름이 잘리는 부작용이 있어 8초부터 시작하고
   필요할 때만 경계 문맥 보존/중복 제거를 설계한다. 무조건 짧게 자르면 추론 횟수가 늘 수 있다.
3. 시작 시 STT 웜업을 모델 준비 단계에 넣어 첫 실제 발화의 초기 추론 부담을 옮긴다.
   준비 시간은 늘고 지속 사용 지연 개선은 기대하지 않는다. 웜업 출력은 게시/저장하지 않는다.
4. 전사 큐 삽입→추론 시작과 Qt 슬롯 도착 시각을 기록하면 실제 대기/화면 반영을 구분할 수 있다.
   다음 튜닝에서 재시도 횟수·VAD 비용도 함께 측정한다. CPU 스레드나 hotwords 변경은 이 근거 이후다.
5. 여전히 긴 꼬리 지연이 문제면 온도 재시도 제한·best_of 축소를 별도 비교한다.
   인식 정확도가 떨어질 수 있어 단순 속도 설정으로 즉시 적용하지 않는다.

추천 첫 단계는 400→300ms와 시작 웜업이다. 연속 발화가 주요 불편이면 8초 분할을 추가한다.
새 큐를 없애거나 이전의 음성 삭제 동작으로 되돌리지 않는다.

## 자막 표시 수정 완료

사용자가 현재 폰트/공간으로 최대한 많은 자막을 보여주도록 요청했다.
기존 config max_lines=3과 코드 최소 5의 결합으로 최근 5발화만 남기던 제한을 제거했다.
36px 글꼴/굵기는 유지하고 읽기 전용 QPlainTextEdit의 기본 줄바꿈/창 크기 배치를 사용한다.
최신 발화로 자동 스크롤하며 이전 기록은 위로 스크롤해 볼 수 있다.
메모리는 ui.caption_history_blocks=200개의 본문 블록으로 제한한다. 표시 가능한 줄 수 제한이 아니다.
전체 수업 TXT의 보관량은 변경하지 않았다. 한 자막에 여러 줄이 있으면 여러 블록으로 계산된다.

매번 전체 본문을 재설정하지 않고 새 자막만 append한다. 인식 모델·인식 설정·진단은 수정하지 않았다.
전체 기존 96개 테스트 통과(10.151초). 별도 offscreen 렌더로 1920×1080에서
자막 viewport 1570×753, 짧은 테스트 문장 약 14줄 표시를 확인했다.
1000×700 리사이즈·밝은/어두운 테마·250회 추가 후 200블록 한도/최신 위치도 확인했다.
실제 화면에서는 글꼴/DPI·알림 표시·문장 길이에 따라 표시 줄 수가 달라진다.
미커밋 수정은 자막 UI/config와 이 기록이다.
